## 引言

本文档旨在详细阐述交通仿真系统前端项目（traffic_sim_frontend）的系统架构设计。通过本指南，开发者可以深入理解项目从路由层、状态管理、业务组件到核心图形渲染引擎的交互流程，为后续的二次开发、性能优化和模块维护提供全局视角的参考。

## 架构设计原则

-   **响应式与组件化**: 依托 Vue 3 的 Composition API 和 `<script setup>` 语法，实现业务逻辑的高效复用与视图的响应式更新。
-   **模块化与解耦**: 严格区分视图层（Views）、业务逻辑（Mods/Stores）、数据访问层（APIs）和图形渲染引擎（SimPIXI）。
-   **高性能渲染**: 针对交通仿真场景中海量动态元素（车辆、信号灯）的特点，引入 WebGL 技术的 2D 渲染引擎 Pixi.js，替代传统的 DOM/Canvas 方案。
-   **安全性优先**: 通过前端路由守卫（Router Navigation Guards）与 Axios 拦截器相结合，构建坚固的权限与认证防线。

## 核心组件交互模型

1.  **视图与状态 (View-Store)**
    组件（如 `SimPIView.vue`、`AsideMenu.vue`）不直接管理复杂的全局状态，而是订阅 Pinia Store。当用户登录成功后，Token 被存入 localStorage，用户信息保存在 `AuthStore` 中，菜单组件根据 Store 中的角色信息（如 `isAdmin`）动态渲染导航项。
2.  **视图与路由 (View-Router)**
    Vue Router 的 `beforeEach` 守卫是系统的门神。它在每次页面跳转前，检查目标路由的 `meta` 字段（如 `requiresAuth`、`roles`），如果用户未登录或权限不足，则中断跳转并重定向到登录页。
3.  **视图与通信 (View-Network)**
    业务页面通过导入 `src/apis` 目录下的函数发起 HTTP 请求。Axios 实例（`src/mods/Axios.ts`）在底层拦截所有请求，自动附加 `Authorization: Bearer <token>` 请求头；同时拦截所有响应，遇到 401 状态码则触发登出逻辑。对于实时仿真数据，视图组件负责建立和管理 WebSocket/SSE 连接。

## 渲染架构演进 (Canvas vs Pixi.js)

交通仿真系统的核心难点在于如何流畅地渲染成千上万辆实时移动的汽车以及频繁切换的信号灯。前端项目经历了渲染架构的升级：

### 1. 传统 Canvas (遗留架构)
-   **实现**: 位于 `src/views/SimSteps/js/sim.js` 等文件中。
-   **用途**: 主要用于静态图形的生成（如路网预览缩略图 `generate_thumbnail`）。
-   **局限**: 基于 `CanvasRenderingContext2D` 的逐帧绘制，在元素数量达到数千时，性能下降明显，且事件交互（如点击某辆车）难以实现，因为 Canvas 本质上是一张位图。

### 2. Pixi.js 引擎 (现代架构)
-   **实现**: 封装于 `src/mods/SimPIXI.ts` 中。
-   **优势**: 基于 WebGL，利用 GPU 硬件加速 2D 渲染；采用场景图（Scene Graph）和精灵（Sprite）机制。
-   **工作机制**:
    -   **底图 (Background)**: 调用遗留 Canvas 工具生成的静态路网图作为底图 Sprite，避免每帧重绘复杂的道路网格。
    -   **坐标转换**: 建立了一套与后端 XML 地图匹配的坐标转换逻辑（`convertCoordinateX/Y`），将原始地图坐标平移至 Pixi 画布坐标系。
    -   **动态元素**: 车辆（`VehPIXI`）和相位信号灯（`PhasePIXI`）作为独立的 Sprite 或 Graphics 对象添加到舞台（Stage）。
    -   **高性能更新**: `updatePlaybackFrame` / `moveVeh` 仅需更新精灵的 `x`, `y` 和 `rotation` 属性，Pixi 内部高效处理渲染管线。
    -   **交互**: 开启精灵的 `eventMode`，轻松实现对车辆和信号灯的点击捕获、高亮放大以及画布的拖拽平移和鼠标滚轮缩放。

## 网络通信层架构

系统根据不同的数据特性，采用了三种通信协议：

1.  **RESTful API (Axios)**
    -   用于常规的 CRUD 操作、用户认证、地图管理和仿真任务配置提交。
2.  **Server-Sent Events (SSE)**
    -   **主要应用场景**: 仿真回放（`SimReplayView.vue`）。
    -   **特点**: 单向（服务端到客户端）的数据流。适合从后端拉取按时间序列组织的历史仿真步数据（`start`, `data`, `seeked`, `end` 事件）。通过 `EventSource` / `fetch` API 建立长连接，并在前端通过状态机解析文本流为 JSON 对象。
3.  **WebSocket**
    -   **主要应用场景**: 实时仿真监控（`SimPIView.vue`）和引擎管理。
    -   **特点**: 全双工双向通信。用于发送实时控制指令（如启动、暂停）并接收高频的仿真帧数据和统计指标。通常配合 `socket.io-client` 或原生 WebSocket API 使用。
